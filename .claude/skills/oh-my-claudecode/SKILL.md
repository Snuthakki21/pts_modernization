Apply [the shared Start workflow](../../../prompts/START_MODERNIZATION.md) and
[technical contract](../../../docs/TECHNICAL_REFERENCE.md) first. This is an
adapted instruction-only skill, not the full upstream plugin. It grants no tools
or permissions. Keep raw source/PII protected; use synthetic or explicitly
approved sanitized views. Preserve legacy behavior, immutable evidence, one
Coordinator writer and actual human approval. Do not install or invoke upstream
runtimes, MCP servers, hooks, proxies or background services.

Identify the observable behavior and existing owner. Reuse the current Coordinator, test tools and evidence paths; do not install a team runtime or second lifecycle engine.

Run existing focused tests first. Where coverage is missing, add a meaningful boundary or adversarial regression and execute the actual implementation. Then run type/build checks, complete repository tests, mandatory named reviews and the scenario campaign required by the operating contract.

Use interactive validation where automation cannot prove the operator flow. Record host, source/build hashes, exercised paths and limitations. Synthetic walkthroughs are not an authentic SME return or live native mainframe acceptance.

Classify every result as passed within scope, failed, blocked or unverified. Keep failures visible and name the exact missing prerequisite. Do not claim completion solely from a plan, tool availability, test count or configuration.

Record findings and receipts in existing structured engineering evidence. Preserve immutable process artifacts and source behavior. No model answer substitutes for human review or observed parity.

Adapted scope: verification-before-completion. Autonomous loops, background agents, hook systems, memory, notification integrations, install scripts and auto-publishing are excluded.
