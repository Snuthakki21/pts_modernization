Your six-step start

  1. Install and open

    Use CPython 3.12. Run scripts/Start.ps1 on Windows or bash scripts/start.sh on Linux/macOS. The launcher prepares the environment when needed and opens the UI after startup. The operator guide gives exact commands.

  2. Save your settings

    Choose the local source folder or upload-at-intake mode, optionally enter a process notes file, then click Save setup. Optional fields hold exact mounted locations and already approved retrieval settings. Saved local defaults apply immediately and after restart. Setup does not contact source systems or certify connectivity.

  3. Provide source and context

    Use the saved export folder or upload the complete source and supply the ordered job/step manifest. Put Devin articles in knowledge/inbox/context.md, custom facts in knowledge/application-knowledge.json and mounted WEDLX bindings in knowledge/input-locations.json.

  4. Start and follow the gate

    Claude Code reads approved local files, analyzes source, implements adapters, runs randomized tests and independent review, then refreshes and submits the current task through the local runner. Claude has no MCP servers, including in its approved VS Code extension. When evidence is missing, Evidence → Claude workspace gives a copyable Copilot retrieval prompt and an exact return folder. Copilot only retrieves the requested files through existing approved MCP tools. Return to Claude and say Continue: checksums, source identity and dependencies must validate before progression. Choose requirements (default Yes), mark unwanted behavior No and Save the Markdown conversion input; return the one actual human SME checklist when issued.

  5. Return one checklist

    Give the actual SME the Yes / No / Not sure workbook. Import their named return once. Supported synthetic tests, comparisons, adversarial checks and reporting continue automatically; unresolved answers stay blockers.

  6. Read numbers and evidence

    Open the process executive report and six-slide PowerPoint. View rule totals by job/program, business versus technical logic, source/target mappings, test results and reasons for unconverted code. Use Effort & scale for measured work, credit receipts and remaining-estate forecasts; forecasts update from accepted pilot evidence while historical reports retain their numbers. Completed with blockers means unresolved work.

Known review findings

The 2026-10-07 advisory review reproduced three functional defects and one outdated instruction. They remain unresolved in this published POC:

  1. Large integer precision: the online form rounds some supported integers above JavaScript's safe integer range, affecting input, displayed output and decisions.
  2. Retrieval recovery: retrieval path validation misses parent/child file conflicts. A conflicting return can leave a process stuck in IMPORTING.
  3. Rule attribution: job/program rule reports can attribute shared copybook rules to programs that do not execute in that job.
  4. Effort guidance: the effort panel still refers to an MCP measurement bridge. Claude must use the documented local measurement-file workflow.

Existing tests pass; these reproductions expose gaps in that coverage. Details and correction directions are recorded in the consolidated evidence file.
